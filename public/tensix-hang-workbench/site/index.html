Tensix Hang Workbench

When a Galaxy model hangs, engineers manually cross-reference watcher.log, tt-triage callstacks, and kernel source across hundreds of cores. This workbench connects those artifacts into a causality receipt with a named root blocker.

plan → run → doctor → report mock mode receipt JSON

Problem

Watcher shows where cores are stuck. Triage shows which line. Neither tells you the causal chain across mcast/CB handshakes.

Solution

Parse hang artifacts → build causality graph → doctor names root blocker (e.g. cb_reserve_back on 768 readers).

Not the PR

Separate from tt-metal Compiler Explorer docs. This targets runtime hang forensics, not SFPI assembly inspection.

CLI (60 seconds)

pip install -e ".[dev]"
tensix-hang run --demo deepseek-quad-mcast
tensix-hang doctor latest --json
