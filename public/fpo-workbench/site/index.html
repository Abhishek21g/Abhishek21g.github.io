The problem Amazon FAR users describe

Pain (public)
"I observe a significant performance cliff at around 4K steps when I extend the training steps to 5K… 4096 environments on a single NVIDIA 3090."
fpo-control#4
Solution

fpo-workbench plan → run → doctor → report on any FPO++ log directory. Produces a portable receipt: hyperparams, checkpoints, multi-signal health grade, paper baseline comparison.

What it separates
  • Paper match — peak reward vs G1/H1/Go2/Spot targets
  • Cliff — post-plateau collapse (not just #4)
  • Flow dynamics — KL, surrogate proxy, obs-norm drift
  • Checkpoint trust — which model_*.pt are safe

    CLI docs

    Why not just TensorBoard?

    TensorBoard / W&B

    • Generic scalars — you eyeball curves manually
    • No paper baseline overlay per robot
    • Flow-specific hyperparams scattered in YAML
    • No portable receipt for sweeps or CI

    FPO++ Training Workbench

    • plan — pre-run risks (EMA, epochs, iter budget)
    • run — ingest logs + checkpoint manifest
    • doctor — 4 signals + baseline grade
    • report — Markdown + JSON receipt trail

    60-second local demo

    pip install fpo-workbench
fpo-workbench demo --out out/demo
fpo-workbench doctor out/demo/receipts/<run-id> --json
fpo-workbench report out/demo/receipts/<run-id>

    Independent of any single upstream PR.

    Useful before and after bugfixes — grades any FPO++ locomotion run from log artifacts. Built for researchers reproducing amazon-far/fpo-control.
