Is your collection actually ready for search?

xAI gives you Collections APIs and a multi-stage indexing pipeline — but no plan → run → doctor → report kit for CI. This is the operational layer Grok RAG teams need before shipping, anchored on indexing pain #77.

mock mode 17 tests 3 scenarios receipt JSON

The solution

Problem

Upload succeeds, but search returns nothing. Docs sit in embedding for hours. Failures are buried in per-document polling. Teams ship RAG pipelines blind — exactly what #77 describes.

Solution

grok-collections run executes a scenario contract (probe → upload → index → search → chat), writes a receipt bundle, and doctor flags backlog, failures, and RAG readiness before you merge.

What it validates
  • Probe health — API + management channel checks
  • Indexing state — processed / failed / in-flight counts
  • Search smoke — RAG path actually returns matches
  • Multimodal paths — image refs resolve for vision chat

One loop for the whole pipeline

1
Plan

Validate scenario YAML, expectations, and step order.

↓
2
Run

Execute probe → upload → index → search → multimodal in mock or live mode.

↓
3
Doctor

Apply rules: backlog, stuck docs, RAG-not-ready, search failures.

↓
4
Report

Emit manifest + summary + steps + findings JSON and markdown report.
